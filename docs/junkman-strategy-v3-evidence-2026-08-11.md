## Heatmap 的正确角色

Heatmap 的金色、紫色或 GEX 正负号不能直接映射多空。junk_man 明确说明两种颜色都可能形成支撑或阻力，方向必须由价格相对节点的接受/拒绝决定（`1523014741591720018`）。

v3 因此只检查候选 tested node 是否靠近 fresh 的高亮/排名结构节点，不再用 Heatmap GEX 符号确认方向。Heatmap 缺失、陈旧或服务降级时保持 neutral；若数据 fresh 且策略要求 tested node 必须为高亮节点，找不到附近节点时才拒绝候选。

## 0DTE Flow 的正确角色

Nightwatch 官方语义：

- 🟢 是 Call，🔴 是 Put，不等于最终看涨或看跌。
- `买` 是 ask 侧主动成交，无法区分开仓、平仓或对冲。
- `⚡` 是 Sweep，表示执行更急迫，不提供可证明的胜率加成。
- `▣` 是 floor/block，`⇆` 是多腿。

官方文档：[0DTE Flow Alert](https://docs.yehangshe.com/discord/flow-alert)、[Flow 字段](https://docs.yehangshe.com/dashboard/uw-flow)、[交易框架](https://docs.yehangshe.com/trading-framework)。

本地频道存在一条消息内多条 alert、同 payload 每 15–30 秒重复、以及显式 `1DTE`。解析器因此：

1. 严格锁定服务器、频道、机器人作者和 `bot=true`。
2. 用全局匹配拆分同一消息内的每条 alert。
3. 先按 `sub_event_id` 归档，再按 payload 指纹在决策窗口内幂等。
4. 只允许延迟不超过 15 秒的 live Gateway `MESSAGE_CREATE` 进入上下文；REST 回填只归档。
5. 显式非 0DTE、颜色与 C/P 不一致、名义金额校验误差超过 10% 均隔离。

junk_man 对高质量 Flow 的描述集中在“大额、OTM、Sweep、同 strike/同方向重复、结合 vol/OI”，并多次认为 SPX Flow 比 SPY 更直接（`1526338968029757451`, `1529060310244261951`, `1532523883645636659`, `1513955649489207426`, `1529064981168128020`）。同时他也明确表示没有大单仍可能出现机会（`1513965401451790547`）。

所以 v3 的 Flow 只做确认上下文：必须是 live、0DTE、SPX、ask、大额、OTM、Sweep、同 strike 至少两条且质量完整。SPY 只审计。Flow 缺失、沉默、单条、延迟或反向都不能自行触发或否决交易。

## Nightwatch API 与 moomoo 的分工

- Nightwatch：Dealer GEX snapshot/history、Heatmap snapshot、配额/健康，以及候选合约的 chain snapshot 审计。
- moomoo：实时 SPY OHLCV/VWAP、SPXW 合约选择、bid/ask、OI、当日成交量、模拟下单、成交和持仓退出。
- Discord Flow：可选的高质量确认上下文，不是依赖。

API 的 OI 可能具有结算滞后，未知 schema、未来时间、过期记录、合约/到期/方向不匹配都不得被猜成方向信号。Nightwatch 当前 REST 能力不能替代 Discord 的逐笔 Flow，但本策略不依赖 Flow 才能产生候选。

## 工程风控，不冒充本人原话

- 仅 moomoo 模拟交易，代码硬拒绝实盘。
- 独立 10,000 美元资金基准；单笔目标 5%、上限 10%，最多 1 个持仓、每天最多 3 笔、日内已实现亏损上限 300 美元。
- 09:45–15:15 ET 才允许新开仓；15:30 开始纪律退出，15:45 强制退出，不隔夜。
- 2026 Cboe 交易日历、早收市处理、报价新鲜度、点差/滑点、可见流动性、OI 与当日成交量门槛。
- 原子状态、订单意图日志、broker-first 恢复、未知提交永久隔离，避免重启重复下单。
- 状态、备注、日志和启动路径均为 JUNKMAN 独占，不会启动其他策略。

## 有意不混入当前单腿 0DTE 线路的内容

- 正 Gamma 下的 butterfly、calendar、credit spread 等定义风险多腿结构。
- 1DTE/周度模型。
- 数日到数月的 OI、skew、事件与基本面预测。
- 尚无可靠机器可读输入的主观高周期 Fib、PMH/开盘叙事和人工路径图。

这些内容在本人资料中存在，但与当前 SPX 0DTE 单腿模拟线不是同一个可执行模型。把它们静默塞入现有下单器会制造无法验证的自由裁量，因此只保留为后续独立策略研究，不用于 v3 自动下单。
