## Heatmap 的正确角色

Heatmap 的金色、紫色或 GEX 正负号不能直接映射多空。junk_man 明确说明两种颜色都可能形成支撑或阻力，方向必须由价格相对节点的接受/拒绝决定（`1523014741591720018`）。

v3 因此不再用 Heatmap GEX 符号确认方向，也不再用没有本人原话或官方数值依据的“附近多少点”去否决候选。Heatmap 只保留为 fresh 时的结构确认上下文；缺失、陈旧、未排名或服务降级均保持 neutral，不能触发或否决交易。

## 0DTE Flow 的正确角色

Nightwatch 官方语义：

- 🟢 是 Call，🔴 是 Put，不等于最终看涨或看跌。
- `买` 是 ask 侧主动成交，无法区分开仓、平仓或对冲。
- `⚡` 是 Sweep，表示执行更急迫，不提供可证明的胜率加成。
- `▣` 是 floor/block，`⇆` 是多腿。

官方文档：[0DTE Flow Alert](https://docs.yehangshe.com/discord/flow-alert)、[Flow 字段](https://docs.yehangshe.com/dashboard/uw-flow)、[交易框架](https://docs.yehangshe.com/trading-framework)。

本地频道存在一条消息内多条 alert、同 payload 每 15–30 秒重复、以及显式 `1DTE`。解析器因此：

1. 严格锁定服务器、频道、机器人作者和 `bot=true`。
2. 用全局匹配拆分同一消息内的每条 alert。
3. 先按 `sub_event_id` 归档，再按 payload 指纹在决策窗口内幂等。
4. 只允许延迟不超过 15 秒的 live Gateway `MESSAGE_CREATE` 进入上下文；REST 回填只归档。
5. 显式非 0DTE、颜色与 C/P 不一致、名义金额校验误差超过 10% 均隔离。

junk_man 对高质量 Flow 的描述集中在“大额、OTM、Sweep、同 strike/同方向重复、结合 vol/OI”，并多次认为 SPX Flow 比 SPY 更直接（`1526338968029757451`, `1529060310244261951`, `1532523883645636659`, `1513955649489207426`, `1529064981168128020`）。同时他也明确表示没有大单仍可能出现机会（`1513965401451790547`）。

所以 v3 的 Flow 只做确认上下文：必须是 live、0DTE、SPX、ask、大额、OTM、Sweep、同 strike 至少两条且质量完整。SPY 只审计。Flow 缺失、沉默、单条、延迟或反向都不能自行触发或否决交易。

## Nightwatch API 与 moomoo 的分工

- Nightwatch：Dealer GEX snapshot/history、Heatmap snapshot、配额/健康，以及官方期权链的方向 gross Gamma-OI 排名代理与候选合约审计。
- moomoo：实时 SPY OHLCV/VWAP、SPXW 合约选择、bid/ask、OI、当日成交量、模拟下单、成交和持仓退出。
- Discord Flow：可选的高质量确认上下文，不是依赖。

Dealer GEX 的 `strikes` 只有逐节点 `net_gex_usd`，官方明确不提供逐节点 Call/Put 拆分；程序不得虚构 `call_gex_usd` / `put_gex_usd`，也不得把只代表行权价位置的 Call/Put Wall 当成方向 GEX 金额。该接口最多返回 5 个产品可见排名节点，因此程序所称“下一结构节点”只是这份有限投影中的下一项，不是假装拥有完整全链分布。Gamma Flip 只保留为 summary 审计上下文，不会被人工合成为候选节点；这与 junk_man“我一般不怎么看 flip”的原话一致（`1525288914926174329`）。Call/Put Wall 只有与返回 strike 重合时才给该节点加标签，不声称缺失 wall 已参与决策。方向合约参考改从官方 `options.chain_snapshot` 的逐合约 Gamma 与结算 OI 计算；同一标的、到期和方向内，`gamma × open_interest` 与传统 gross GEX 金额具有相同排名，公共的现价和乘数因子无需参与排序。这是方向 strike 排名代理，不冒充 Nightwatch Dealer GEX 或盘中方向信号。

官方字段依据：[Dealer GEX API](https://docs.yehangshe.com/api/dealer-gex)、[options — 期权结构](https://docs.yehangshe.com/api/domains/options)、[Dealer 与传统 GEX 的区别](https://docs.yehangshe.com/concepts/dealer-vs-traditional-gex)。

API 的 OI 具有结算滞后，只用于合约 strike 排名和流动性背景，不作为盘中方向信号。生产只读响应已观测到 `data.contracts[].contract_symbol`、`snapshot_at`、`greeks_as_of`、`open_interest_as_of` 和 `_meta.truncated`；公开 OpenAPI 只把 200 payload 声明为 object，因此代码把这些字段称为“实测官方响应 + 工程 fail-close”，不冒充公开 schema 的逐字段保证。同一完整 chain 响应同时用于 strike 排名与候选合约审计，避免一次 setup 重复消耗两次相同付费请求。Nightwatch 当前 REST 能力不能替代 Discord 的逐笔 Flow，但本策略不依赖 Flow 才能产生候选。

## 工程风控，不冒充本人原话

- 仅 moomoo 模拟交易，代码硬拒绝实盘。
- 独立 10,000 美元/线资金基准；单笔目标 5%、10% 为软目标，单张不超过整条虚拟资金。活动策略没有无出处的每线 3 张上限；物理聚合单为 7 × 每线预算/盘口深度算出的数量。当前执行器一次只管理 1 个 JUNK-owned cohort。无本人依据的“每天最多 3 笔”和“日亏 300 美元停手”已禁用。
- Nightwatch 只定性提示盘前与最后 15 分钟节点可靠性/流动性下降；09:30–15:45 新开仓、15:45 纪律退出、15:55 强平及不隔夜均是本项目工程调度，不称作 JUNKMAN 或官方精确时间规则。
- 30 秒信号寿命、600 秒 GEX 时效、3 秒报价时效、5 秒未来偏差和 45 秒订单 TTL 是数据/订单一致性约束；2026 Cboe 日历与早收市处理也是运行有效性约束，不是交易形态门槛。
- 合约必须有真实 bid/ask、tick 和正的可见 ask；下单数量不超过当前显示 ask。OI 与当日成交量继续记录，但 JUNKMAN 与官方执行文档都没有给出可作为硬门的最低值，因此不再用它们否决入场。不再叠加无出处的点差 20%、往返损失 25%、OI 100、成交量 100、每线合约数或 300% 可见深度门槛。1 tick 模拟滑点是工程成交模型；立即退出损失超过 -15% 时拒绝，是从本人 10–15% 区间取上沿的工程实现。
- 候选合约审计只在明确的合约身份、到期或方向冲突时否决；缺失、未知或陈旧的辅助审计证据保持 neutral。方向链本身仍必须通过与主 GEX 策略一致的 600 秒数据有效性检查，不再叠加更严格的 300 秒隐性否决。
- JUNKMAN 只给出方向最大 GEX strike 的 ±5–10 范围，没有定义加减号如何选择；当前“向现价偏移 5 点”是可审计的工程启发式，后续如获得本人明确口径应直接替换。
- Provider 未给节点区域宽度，程序用影线实际触及 strike 作为“触节点”的无数值容差实现，不自行发明 0.5/1.5 点阈值。突破可由一根实体穿越 K 开始，随后连续 K 只需守住接受侧，最终由触节点的影线回踩 K 确认；一般拒绝只看最新一根完整 5m K。VWAP、GEX 历史样本和最近节点 Gamma 符号只记为上下文，不作隐藏 veto。
- 成交量字段必须为真实正值，但证据没有给出可自动化的倍数，所以程序不虚构成交量比率，也不把“字段存在”伪装成强弱结论。完整确认 K 在后续轮询中继续有效；不再叠加 90 秒失效、固定实体点数、固定突破位移、固定入场漂移或 15 分钟冷却。
- 当前 `reward > risk` 是工程上的 1.0 最小形式化；Nightwatch 官方原意是“接近 1:1 往往仍不足、回报应明显大于风险”，并未推荐精确 1.0 或 1.33。1.33 旧门槛已删除。
- 本人止损原话是期权入场 K 上/下几毛；当前 `underlying_confirmation_bar_wick_proxy` 是在缺少可靠期权 K 输入时的透明代理。-15%、结构目标 50% 分批、七线精确 TP/SL 网格、15:45/15:55 均明确属于工程/实验选择。
- 实验汇总 PnL 按 `(退出价 - 入场价) × 数量 × 100` 计算，字段明确标记为 gross option-price PnL、未计 broker fees。
- 原子状态、订单意图日志、broker-first 恢复、未知提交永久隔离用于避免重启重复下单；状态、备注、日志和启动路径均为 JUNKMAN 独占。

## 有意不混入当前单腿 0DTE 线路的内容

- 正 Gamma 下的 butterfly、calendar、credit spread 等定义风险多腿结构。
- 1DTE/周度模型。
- 数日到数月的 OI、skew、事件与基本面预测。
- 尚无可靠机器可读输入的主观高周期 Fib、PMH/开盘叙事和人工路径图。

这些内容在本人资料中存在，但与当前 SPX 0DTE 单腿模拟线不是同一个可执行模型。把它们静默塞入现有下单器会制造无法验证的自由裁量，因此只保留为后续独立策略研究，不用于 v3 自动下单。
